# AR Marker Angle & Border Visualizer + WebSocket Relay

Автономний модуль WebAR та сервер ретрансляції для:
- візуалізації зеленої рамки навколо маркерів:
  - BarCode-маркерів (матриця 3x3);
  - ArUco-маркерів (словник 4x4_1000), генерація зображень - https://tagsgen.top/
- визначення кута нахилу відносно горизонту та передачі значення `"angle_x"` через WebSocket у Scratch чи інші застосунки.

## Можливості
- **Вибір вебкамери:** підтримка декількох камер через аргумент командного рядка (`--camera=0`, `--camera=1`) або випадаючий список у веб-інтерфейсі.
- **Зелена контурна рамка:** апаратно рендериться на GPU навколо периметра кожного виявленого маркера (Zero-Lag).
- **Визначення кута нахилу:** обчислює кут нижньої сторони маркера відносно горизонтальної осі екрана в діапазоні `[-180°, +180°]` (де `0.0°` відповідає горизонтальному положенню).
- **Вимірювання та візуалізація швидкості переміщення (X-Y):** розрахунок поточної швидкості у сантиметрах на секунду (`cm/s`) за допомогою динамічного оптичного масштабування та фіксація максимальної досягнутої швидкості `Speed-max` у нижній частині екрана (нижній HUD). Гаряча клавіша `r` скидає зафіксований максимум.
- **Виведення значення кута:** 3D-плашка (Sprite billboard) у браузері або нативний 2D HUD у вікні OpenCV, орієнтовані на користувача.
- **WebSocket ретрансляція (20 Гц):** автоматично надсилає дані кута нахилу та швидкості у форматі `{"accX": 0, "accY": 0, "angle_x": <кут>, "angle_y": 0, "marker_id": <id>, "speed_cm": <швидкість>, "max_speed_cm": <макс_швидкість>}` на порт `8767` для передачі даних до TurboWarp Scratch-середовища розробки.
- **Автоматичний запуск однією командою:** запуск локального HTTP-сервера та WebSocket-сервера ретрансляції даних про маркери:
  - `python barcode_marker_angle_visualizer_web.py` — для роботи з BarCode-маркерами через браузер;
  - `python aruco_marker_angle_visualizer_web.py` — для роботи з ArUco-маркерами через браузер;
  - `python aruco_marker_angle_visualizer_desktop.py` — для роботи з ArUco-маркерами через нативний Desktop (OpenCV). Підтримує аргументи `--marker-size` (за замовчуванням: `3.0` см) та `--fast-shutter` (режим короткої витримки для мінімізації Motion Blur).

## Якість розпізнавання маркера: проблеми та рекомендації

Стабільність детекції, точність вимірювання кута та коректність обчислення швидкості напряму залежать від умов оптичного середовища та параметрів камери. Нижче наведено типові фактори, що впливають на якість розпізнавання, та шляхи їх усунення.

### 1. Оптичне змазування при швидкому русі (Motion Blur) та втрата контролю
* **Проблема:** При різкому переміщенні маркера в кадрі зникає зелена контурна рамка, маркер перестає розпізнаватися (`ids is None`), а поточна швидкість скидається. Причина — тривала витримка веб-камери (shutter speed), через яку чорно-білі біти сітки ArUco змішуються у сіру розмиту пляму.
* **Рішення:**
  * **Збільшити освітленість:** При яскравому світлі алгоритм автоекспозиції камери автоматично скорочує витримку (наприклад, з 1/30 с до 1/250 с і менше), що кардинально усуває розмиття.
  * **Збільшити фізичний розмір маркера:** Для розміру 3 см окремі біти становлять лише ~5 мм. Збільшення маркера до **5–7 см** робить біти більшими за радіус оптичного змазування, дозволяючи зберігати детекцію на швидкостях у 2–3 рази вищих.
  * **Ручні налаштування камери:** Якщо веб-камера підтримує ручне керування, вимкніть автоекспозицію та встановіть фіксовану коротку витримку.

### 2. Умова безперервності трекінгу між кадрами
* **Особливість алгоритму:** Обчислення швидкості $\frac{\Delta d}{\Delta t}$ є математично та фізично коректним **лише за умови наявності неперервного контролю маркера між сусідніми кадрами**.
* Якщо маркер зник через змазування на кілька кадрів і знову з'явився в іншій точці, алгоритм не здійснює хибних стрибків швидкості («телепортації»). Перший кадр після повернення маркера слугує виключно новою точкою відліку, а показник `Speed-max` зберігається без спотворень.

### 3. Бліки, відблиски та якість виготовлення маркера
* **Проблема:** Дзеркальні відблиски від ламп на екрані смартфона чи на глянцевому фотопапері створюють білі плями поверх чорних комірок матриці, через що контрольна сума бінарного коду не проходить перевірку.
* **Рішення:**
  * Друкувати маркери на **матовому папері** або уникати спрямованого джерела світла під кутом дзеркального відбиття в об'єктив камери.
  * Наклеювати паперовий маркер на жорстку плоску основу (цупкий картон, пластик). Згинання площини маркера спотворює його геометричну форму.
  * Обов'язкова наявність чистого **білого поля (Quiet Zone)** завширшки не менше 1 біта навколо чорного зовнішнього контуру ArUco-маркера.

### 4. Недостатнє освітлення та сенсорний шум (Jitter)
* **Проблема:** У напівтемряві камера підвищує коефіцієнт підсилення (ISO), що призводить до високого цифрового шуму (зернистості). Це викликає випадкове субпіксельне дрижання координат кутів навіть у нерухомого маркера.
* **Рішення:**
  * Забезпечити рівномірне розсіяне освітлення сцени.
  * Вбудована мертва зона (deadband threshold = 1.5 px) та фільтр EMA автоматично гасять цей шум, утримуючи швидкість на рівні `0.0 cm/s` у спокої.

### 5. Перспективні викривлення при сильному нахилі
* **Проблема:** При значному відхиленні площини маркера від нормалі до осі камери (нахил «від себе» чи «до себе») квадратний маркер проектується у вузьку трапецію, що ускладнює зчитування бітів.
* **Рішення:** Для вимірювання швидкості у площині X-Y намагайтеся тримати маркер орієнтовно паралельно до площини матриці камери.

## Експериментальне програмне забезпечення
Для перевірки роботи маркерів можна використати програму, розміщену в каталозі TurboWarpApplications\4-Cat-Run-SmartPhone.sb3

Програма містить наступний сценарій гри:
- котик біжить по доріжці, на якій періодично з'являються перешкоди;
- щоб оминати перешкоди необхідно змінювати доріжку бігу котика
- для зміни доріжки треба нахиляти маркер вліво/вправо, змінюючи кут нахилу маркера відносно горизонту;
- після зміни доріжки треба повертати маркер у горизонтальне положення.
